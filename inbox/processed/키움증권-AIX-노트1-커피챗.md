# 키움증권 AIX 직무 지원 참고 노트
> 출처: 2026.09.05 박인준 주임(키움증권 AIX팀) 커피챗 녹취 (클로바노트 자동변환)
> ※ 자동변환 오타가 있어 일부 표현(예: "키우Me", "X스튜디오")은 문맥상 추정입니다.

---

## 1. AIX팀은 어떤 팀인가

| 항목 | 내용 |
|---|---|
| 역할 | **대직원(사내) AI 업무 효율화** 담당. 작년까지는 대고객·대직원을 모두 했으나 올해부터 분리됨 |
| 대고객 AI | 별도 팀("X스튜디오"로 들림)이 담당 |
| 팀 구성 | 대부분 경력직(금융권 경력 또는 IT 출신). 신입은 작년 1명(박인준 주임) + 올해 1명 = 총 2명 |
| 개발 방식 | **개발은 모회사 다우기술에 외주.** 사내에 "개발팀 개발자"는 없음. AIX는 기획·요건정의·개발 검토·프로젝트 관리 성격 |
| PoC | 외부에 보여줄 작은 결과물(PoC)을 만들 때는 직접 개발도 함 |
| 팀장 | 개발 출신 → 백엔드 지식에 대한 기대치가 상대적으로 높음 |
| 사내 AI 환경 | 외부 Claude/GPT가 아닌 **내부 구축 LLM** 사용(성능은 외부보다 낮음). 망분리라 외부 AI 결과물 반입은 정해진 절차(메일 등)로, 민감정보만 제외하면 가능 |
| 참고 | 멘토 지원 당시 키움증권은 챗봇("키우Me")을 진행 중이었고, 멘토의 챗봇 기획 인턴 경험과 맞아 좋게 평가됐다고 함 |

> **핵심 메시지:** "진짜 개발자"를 원한다면 키움과 안 맞을 수 있다. AIX는 현업과 개발팀 사이의 **기획·소통·PM** 역할이다.

## 2. 실제 업무 프로세스 (자소서에 그대로 녹일 수 있는 구조)

### 기획 흐름
1. **니즈 수집** — 부서별 "업무연락"으로 AI 효율화 니즈를 받음
2. **미팅** — 니즈가 있는 부서와 미팅. 처음엔 아무것도 없는 상태에서 시작(부트캠프 1차 프로젝트와 똑같다고 함)
3. **데이터·업무 검토** — 현업이 쓰는 데이터를 받아 검토, 수정 방향 제안
4. **요건 정의 + 문서화** — 현업이 무엇을 원하고 우리가 어떻게 해결할지 명확히 문서화
5. **개발팀(다우기술) 전달** — 문서에 넣는 것:
   - 와이어프레임(화면까지 그려주는 게 가장 좋음)
   - 꼭 들어가야 하는 기능
   - **왜 만드는지** (개발팀을 설득)
   - ※ LangChain, Pydantic AI 등 **프레임워크 지정은 하지 않음** → 개발팀이 결정
6. **결과 검토** — 현업이 A를 말했는데 B로 만들어지면 AIX 책임

### 하루 일과 (멘토 기준)
- 출근 → 담당 사내 AI 프로젝트의 **전일 사용량·에러 확인**
- 개발팀과 **주간 소통** 사항 정리
- **현업용 문서 작업**(가장 비중 큼) + 회의
- 와이어프레임은 초기 기획 때만
- 툴: 사내에서는 워드. 귀찮으면 외부 AI로 초안 만들어 반입

### 왜 중요한가
- 현업 = 개발 지식 없음 / 개발팀 = 현업 지식 없음 → **양쪽 중간에서 통역하는 역량**이 핵심
- 멘토는 입사 전 "소통·문제해결·갈등해결 역량" 질문이 쓸모없다고 생각했지만, **입사 후 실제로 가장 많이 쓰는 역량**이라고 강조

## 3. 채용에서 보는 것 / 안 보는 것

### 보는 것
- **AI 관련 프로젝트 경험** — 개발이면 무엇을 개발했는지, 기획·디자인이면 어떤 AI 프로젝트에서 어떤 역할을 했는지
- 이런 경험이 있는 지원자가 **의외로 적음**. 금융회사 지원자는 경영·경제만 알고 IT를 모르는 경우가 많아 프로젝트 경험이 큰 차별점
- 대회는 **수상 여부보다 그 안에서 무엇을 했는지**
- 회사·팀의 최신 AI 동향에 대한 이해와 내 경험의 연결

### 크게 안 보는 것
- 학력 등 정량 스펙 (팀이 경력직 중심이라 정량 기준 자체가 애매)
- **자격증**(빅데이터, 정보처리기사 등) — "크게 안 본다"고 명시
- 깊은 금융·주식 지식 (AIX 한정, 아래 참고)

### 요구되는 개발 수준
| 의견 | 수준 |
|---|---|
| 박인준 주임 | **파이썬 코드를 읽을 수 있고**, 바이브코딩으로라도 **작은 결과물을 만들어본 경험**이면 충분 |
| 팀장(개발 출신) | 백엔드 통신 등 **백단까지 알면 좋음** |
| 언어 | 파이썬만 알아도 충분 |

### 금융 지식은 얼마나?
- AIX는 딥한 금융 지식 필수 아님. 멘토도 입사 전 주식 거래·MTS 경험 전무
- 단, **최소한의 이해는 필수**: 기본 용어(여신/수신, MTS 등), 이 회사가 어떻게 돈을 버는지
- "직무만 보고 지원한 게 아니다"라는 관심도만 드러내면 충분. 금융은 서브, 직무 역량이 메인
- (참고) 리테일/MTS 플랫폼 직무는 반대로 주식·서비스 이해가 핵심. 리서치도 알아야 함

### 멘토 배경 (참고 사례)
- 인문대 주전공 + 공대(AI) 복수전공
- AI 관련 인턴(챗봇 기획 지원 업무) → 학교 + 인턴 경험으로 자소서·면접 구성
- 금융이 1순위가 아니었고 "AI 기획 직무"가 1순위였음

## 4. 자소서 전략

1. **빨리 제출하라 (비공식 팁)**
   - 마감 후 일괄이 아니라 **들어온 순서대로 읽음**
   - 뒤로 갈수록 읽는 사람이 지치고, 신입 경험은 편차가 크지 않아 비슷한 내용은 앞사람과 비교되어 눈에 안 띔

2. **회사·팀의 최신 AI 동향 조사 → 내 경험과 엮기**
   - 단, 내 경험이 팀이 찾는 사람과 실제로 다르면 겉만 비슷해 보여도 소용없음(운의 요소 있음)

3. **기본기: 가독성**
   - 맞춤법, 구성, 읽는 사람 고려. AI로 다듬는 것 OK
   - 소제목은 읽는 사람 취향 (정답 없음)

4. **프로젝트 서술 방식**
   - 키움은 **깃허브 링크·포트폴리오 PDF 첨부 없음** → 자소서 텍스트로만 보여줘야 함
   - 길이 제한 → **아이템 · 역할 · 수행 내용** 위주로 컴팩트하게
   - "왜 이런 결정을 했나(Why)", 인사이트는 **면접에서 구두로**

5. **추천 아이템: 갈등·소통 오류 해결 경험**
   - 팀 프로젝트에 진심으로 임하면 반드시 의견 차이·소통 오류가 생김 → 이를 해결한 경험이 좋은 자소서 소재
   - 결과물 자체보다 "그 과정에서 무엇을 느꼈나"가 더 중요

6. **서류 필터링 구조**
   - 인사팀이 먼저 선별 → 현업 전달. 인사팀 기준은 현업도 모름(비공개)

## 5. 면접

- **가장 많이 받은 질문: "그래서 여기(이 팀) 와서 뭐 하고 싶어요?"**
  - 스펙 나열보다 이걸 **명확하게** 답하는 사람이 기억에 남음
  - 부서 방향성과 정확히 일치할 필요는 없음(외부인이 정확히 맞추는 건 불가능) → 이 질문은 **산업·직무 이해도 + 적극성**을 총체적으로 보는 것
- 금융 관련 질문은 많지 않고, **직무 역량(프로젝트) 질문**이 중심
- 서류에 못 담은 Why·인사이트를 면접에서 풀기
- 멘토는 작년 2차 면접에 면접관으로 참여했음

## 6. 나(최연준)에게 맞춘 액션 플랜

### 강점으로 연결할 것
- **"사내 AI 업무 혁신" 관심** → AIX가 정확히 대직원 업무 효율화 팀. 방향성 일치
- **리서치 에이전트 / 애널리스트 자동화 프로젝트(백엔드 담당)** → "AI 프로젝트에서 어떤 역할을 했는지"에 정확히 해당. 멘토도 "백엔드 인력은 귀하다"고 언급
- **경영학 전공 + 바이브코딩 독학** → 멘토 기준(코드 읽기 + 결과물 제작)은 이미 충족. 금융 도메인 관심도 어필 가능

### 보강할 것
- [ ] 팀장 성향 고려: **백엔드 통신·API 기본**(요청/응답 구조, 서버-클라이언트 흐름) 설명할 수 있게 정리
- [ ] 키움증권 **최근 AI 동향** 조사 (사내 AI 도입, 챗봇, 대고객 AI 팀 분리 등) → 자소서 지원동기·입사 후 포부에 연결
- [ ] **기본 금융·증권 용어** 학습 (여신/수신, MTS/HTS, 증권사 수익 구조, 리테일/IB/리서치 구분)
- [ ] 자격증·수상은 부각하지 말고 **프로젝트 경험**에 지면 집중

### 자소서 작성 시
- [ ] 프로젝트를 **AIX 업무 프레임**으로 서술: 문제(페인포인트) 발견 → 요건 정의 → 화면/기능 설계 → 개발/구현 → 검토·개선
- [ ] 개발 역량뿐 아니라 **기획·문서화·팀 간 소통** 경험을 함께 보여주기 (AIX는 개발자 채용이 아님)
- [ ] **갈등·소통 오류 해결 아이템** 확보 — 1차 팀은 갈등이 없었으므로 2차 프로젝트에서 의견 충돌을 회피하지 말고 조율 경험 만들기
- [ ] 자소서는 **공고 오픈 직후 빠르게 제출**
- [ ] Why·인사이트는 자소서에 압축, 면접용으로 따로 정리

### 면접 준비
- [ ] "AIX에 와서 하고 싶은 것"을 **구체적으로** 1~2개 준비 (예: 특정 부서 업무 자동화 아이디어, 사내 LLM 활용 개선 등)
- [ ] 프로젝트 각 결정의 **Why** 정리
- [ ] 갈등 해결 사례를 STAR 형식으로 정리
