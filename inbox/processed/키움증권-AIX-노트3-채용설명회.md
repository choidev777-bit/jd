## 0. 이번 녹취에서 새로 알게 된 것 5가지

1. **AIX의 현재 대표 과제는 "사내 LLM(사내 GPT) 구축·운영"**이다. 다우기술을 통해 개발하고 기능 업그레이드·모델 교체를 주관. 사내 AI 공모전·교육·대회도 AIX가 주관.
2. **AI 거버넌스는 아직 확립되지 않은 상태.** JD에 "AI 거버넌스 운영"이 있지만 실제로는 만들어가는 단계 → "제도를 만드는 일에 기여하고 싶다"는 포부가 현실과 맞음.
3. **2차 면접이 PT 면접으로 바뀌었다고 들었다**고 함(멘토 기수 때는 동료·인성 면접). ②편의 "AI활용능력평가면접"은 멘토 기수에는 없었고 다음 기수부터 생김 → 올해 전형은 작년과 또 다를 수 있으니 **안내 메일을 그대로 믿고 준비**.
4. **자소서는 팀장이 한 번, 면접 때 한 번 본다. 기술 용어 나열은 이해 못 한다** → 쉽고 간결하게 "무엇을 경험했고 어떤 역량을 얻었나". 대신 자소서에 쓴 용어에는 100% 꼬리질문이 붙는다.
5. **최종 면접 4명 중 3명이 붙어 각 부서로 흩어졌다.** 옆 지원자와 제로섬 경쟁이 아니고, 역량이 있으면 유관 부서(AIX↔ICT↔X스튜디오↔플랫폼)로 배치될 수 있음.

## 1. 외부(ICT)에서 본 AIX팀

| 항목 | 내용 |
|---|---|
| 정체성 | 생긴 지 얼마 안 된 팀. 대직원(사내) 생산성 향상이 목표. 계속 AI로 "사업을 벌리는" 팀 (ICT는 기존 서비스 유지보수·운영) |
| 대표 과제 | **사내 내부망 LLM 서비스** 구축·운영. 다우기술 통해 개발, 기능 업그레이드, 모델 교체 |
| 부가 역할 | 사내 AI 공모전·교육·대회 주관 |
| 과제 발굴 | 자체 발굴 + 타 부서 요청 **둘 다**, 점차 확대 중. ICT 프로젝트에 AI가 들어가면 AIX를 부르긴 하지만 "참고 검토해 주세요" 수준 |
| 거버넌스 | **아직 확립 안 됨.** 확립하려고 노력 중 |
| 관리 인력 | 실질적으로 관리하는 분이 "두 분 정도"라는 언급 (소규모) |
| 협업 범위 | 시작 단계라 타 부서와 대규모 협업은 아직 적음. **주로 다우기술 AI 개발자·에이전트 개발자와 소통** |
| 하지 않는 것 | AI 모델 개발·연구 (다우기술도 모델을 가져다 쓸 뿐). 단, 연구 경험은 좋게 봄 |
| 실패 허용 | 사용률 저조한 서비스도 있지만 부정적으로 보지 않음. **사장이 매일 AI를 강조**해서 시도 자체를 장려 |

### 사내 LLM의 현실 (역질문·입사 후 포부 소재)
- ICT 현직자의 실제 사용: **보고서 문구 다듬기 정도.** 기술적으로 이해 안 되는 부분 물어보는 용도
- AIX가 자꾸 "어떻게 쓰고 있냐" 물어봄 → 활용도 측정·확산이 AIX의 고민거리
- "AIX가 더 잘 만들어서 외부 Claude Pro처럼 잘 됐으면 좋겠다" → **사내 LLM 활용도 제고·기능 개선**이 입사 후 하고 싶은 일로 말하기 좋은 소재

### AIX 구성원 배경
- 팀장: 타 대기업 개발자 출신
- 부장: 금융 쪽 백그라운드 (IT 아님)
- IT 백그라운드 1명
- 신입 2명: 경영+AI 복수전공(프로젝트 경험) / AI 백그라운드
- 윗분들은 다양, **신규 입사자는 모두 AI 역량 보유**

## 2. 자소서 조언 (ICT 현직자 관점)

### 기술 vs 증권 도메인, 무엇을 강조?
- **자신 있는 것, 면접에서 잘 말할 수 있는 것**을 쓰라. 정답 없음
- 개발을 "잘한다" 어필보다 → **"개발 경험이 있어서 들어오면 이런 일을 할 수 있다"** 프레임
- 증권 경험은 AIX·ICT·X스튜디오 합격자 대부분 없음. 있으면 로열티로 보일 뿐 필수 아님
- **은행·타 업권 AI 경험도 OK.** "은행원용 AI 에이전트 대회 수상"을 써도 되냐는 질문에 "너무 좋다, 상관없다"
- 대고객 서비스 경험도 빼지 말고 쓰라 — AIX 팀장은 **AI 역량과 소통 능력**을 보기 때문

### 읽는 사람을 생각하라
- 팀장은 극도로 바쁨. 자소서는 **서류 때 한 번, 면접 직전 한 번** 보는 게 끝
- "AI 모델 어쩌고, 선형 분석 어쩌고" 식 기술 나열 → **못 알아듣는다**
- 구구절절 나열 X → **핵심을 쉽게, 간결한 소재로, 경험 → 얻은 역량**으로 연결
- 단, 쓴 용어에 팀장이 꽂히면 반드시 물어봄 → **자소서에 쓴 모든 용어는 설명할 수 있어야 함**

### 전공
- 이공계·AI 전공은 정량적으로 플러스 있음
- 하지만 서류는 정량 통과하면 끝. **면접에서 같은 질문에 옆 사람보다 설득력 있게 답하는 사람**이 뽑힘
- 경영학 전공이라도 관련 경험 있으면 충분히 가능 (AIX 동기 사례)

## 3. 면접 정보

### 전형 구조 관련 (변동 주의)
- 멘토 기수: 1차 실무(팀장) → 2차 **동료 면접**(바로 위 사수 대리도 참석, 인성 위주) → 최종. AI 면접·영어 면접 필수 아님
- 그 다음 기수(②편 김재헌 기수): AI활용능력평가면접 추가
- **올해: 2차가 PT 면접으로 바뀌었다고 들음** → 확정 아님. 안내 메일 기준으로 준비
- 영어 면접: **선택적으로 추가 수행** 가능. AIX·ICT는 영어 쓸 일 없음. 멘토는 봤지만 "끝나고 뭐 할 거냐 → 친구랑 점심" 수준. 플러스인지는 불확실. 자신 있으면 가볍게 응시

### 1차(실무·팀장) 면접
- **CS·IT 전공지식 테스트 없음.** OS 같은 거 공부할 필요 없음
- 자소서 기반. 질문 **5~6개 + 각 1개 정도 꼬리질문**
- **말 너무 길게 하지 말 것.** 옆 사람 시간까지 다 써버리는 사람 있었음 (그래도 붙긴 함)
- 질문 예측은 거의 불가능 → 공통 질문만 대비하고 자신감으로

### 멘토가 실제 받은 질문 (자소서 문구 → 꼬리질문 → 증권 적용)
1. 자소서에 "실시간 데이터 통신 트래픽을 이해하게 됐다"고 씀 → "그게 뭐냐?"
2. → "증권사에서 트래픽이 많이 발생하면 어떤 상황이 벌어질 것 같냐? 어떤 상황에서 많이 발생할 것 같냐?" → 공모주 청약 (몇 달간 주식 거래해본 경험으로 답변)
3. 다른 증권사 서비스 써봤나? 우리 앱(영웅문) 써봤나?
4. 우리 앱에서 개선할 점?
5. AI를 어떻게 쓸 것인가?
6. 마지막으로 어필할 것?

→ **패턴: 자소서의 한 문구를 잡아 → 개념 확인 → 키움/증권 상황에 적용 → 우리 서비스 사용 경험 → AI 활용 의견 → 마무리 어필**

### 2차 면접(실무진)에서 보는 것
- 역량은 기본이고, **"이 사람이 내 후배로 왔을 때 말이 통할까"** = 커뮤니케이션
- 인성이 안 중요하다는 게 아니라, 질문에 대한 답변 방식에서 소통 가능성을 봄

### 태도
- **겸손하지만 씩씩하게, 자신감 있게.** 멘토는 팀장들이 험악해 보였지만 긴장 안 하고 봐서 붙은 것 같다고 함
- 인성 질문부터 자소서 기반 질문까지 **전부** 준비
- 면접은 볼수록 는다 (멘토도 9월 지원은 전부 탈락, 11월에 키움 합격)

### 배치
- 지원한 직무로 뽑히면 거의 그대로 배치. 틀어지면 인사팀이 **먼저 연락해서 의향을 물음** (S&T 지원 → 인사팀 배치 사례)
- 최종 4명 중 3명 합격 → 각 부서 배치. **역량 있으면 유관 부서로 갈 수 있다**

## 4. 회사 맥락 (지원동기·역질문용)

- **리테일 강자 유지**가 회사 전략. 리테일이 매일 신규 기획을 ICT에 검토 요청
- 위에서 "**토스 따라 하지 마**"라고 하지만 실제로는 신규 서비스를 계속 출시하고 AI도 많이 쓰는 분위기
- ICT의 역할은 "보수적 검토" — 변화에 보수적인 게 아니라 **기존 시스템·기존 사용자에 영향이 없도록** 조절
- 개발·운영 구조: 현업 기획 → ICT 검토 → 다우기술 개발. ICT는 이슈 관리·일정 관리 위주. 서버·트래픽 모니터링 시스템도 다우가 구축, ICT가 보고 의사결정
- 이슈 관리 툴: 10년 넘은 Jira → 올해 **자체 개발 이슈관리 시스템**으로 전환. 모바일은 Redmine
- 토큰증권(STO): 담당자만 지정, 현재 활성화 안 됨
- 미국 주식 야간 대응: ICT가 24시간 모니터링하지 않음. 별도 인력 운영

## 6. ①②③편 종합 — 최종 액션 플랜 업데이트

### 자소서 (마감 9/13, 빨리 제출)
- [ ] **읽는 사람 = 바쁜 팀장.** 리서치 에이전트 프로젝트를 "멀티에이전트·벡터DB·RAG" 나열이 아니라 **"애널리스트 인터뷰로 문제 찾음 → 검증 에이전트로 팩트체크 → 검수 시간 단축"** 처럼 비개발자가 읽어도 이해되게 쓰기
- [ ] 자소서에 쓴 **모든 기술 용어**를 1분 안에 설명할 수 있는지 점검
- [ ] 개발 "잘함" 대신 → "**개발·기획 경험이 있어서 다우기술 개발자와 말이 통하고, 현업 요건을 문서로 정리할 수 있다**"
- [ ] AIX 현재 과제(사내 LLM 운영·확산, 거버넌스 미확립)와 연결한 **입사 후 포부**: 사내 LLM 활용도 제고, AI 활용 가이드라인 수립 참여 등
- [ ] 경험을 여러 축으로 배분 (②편 교훈) — 프로젝트 / 바이브코딩 독학 / 경영학 기반 현업 이해 / 팀 조율

### 면접
- [ ] **AI 면접(있을 경우)**: 기술 스택·아키텍처를 깊이 있게 (②편 2~3점 기준)
- [ ] **1차 팀장 면접**: 자소서 문구 하나하나에 "그게 뭐냐 → 키움에서는 어떻게 적용되냐" 시뮬레이션
- [ ] **영웅문S# 직접 써보기** + 타사 MTS 비교 + 개선점 1~2개 + "여기에 AI를 어떻게 쓸지" 의견
- [ ] 공모주 청약 등 **증권사 특유의 상황**(트래픽 폭증, 장 시작·마감, 야간 미국주식)을 AI 업무효율화 관점에서 생각해두기
- [ ] **PT 면접 가능성** 대비: 주제가 주어지면 "문제 정의 → 제약(망분리·컴플라이언스) → 해결 → 검증"으로 구조화하는 연습
- [ ] 답변은 짧고 명확하게. 겸손하지만 씩씩하게
- [ ] 영어 면접은 선택 → 부담 없으면 응시

### 일관성 체크
- 커피챗·설명회에서 만난 박인준 주임·김재헌 사원·ICT 현직자가 면접관으로 들어올 수 있음 → 그날 말한 관심사(사내 AI 업무 혁신, AIX 희망)와 자소서·면접 내용을 일치시키기
