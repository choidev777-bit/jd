## 1. AIX 직무 이해

### 1-1. JD 원문 (경영지원 부문 소속)

- AI 거버넌스(위험평가 등) 운영 및 사내 AI 프로젝트 관리

  - 현재: 사내 LLM 구축·운영 (③)
  - 과거: 챗봇 "키우Me"(①, 박인준 주임 지원 당시 진행), 리서치 부문과 AI 리서치 리포트 자동화(②, 작년). ICT 현직자는 AIX 과거 프로젝트를 구체적으로 언급하지 않음
  - 주의: 올해 대고객 AI가 X스튜디오로 분리됐으므로, 과거 대고객 성격 프로젝트는 현재 기준 X스튜디오 영역일 수 있음 (①② 종합, 추정)
  - "사용률 저조 프로젝트" 언급은 AIX 주관 건이 아닌 회사 전반 사례였음 (③)

### 1-3. 팀의 위치와 구성
- 소속: 경영지원 부문(JD) / 전략기획 계열, 인사팀과 같은 부문·바로 옆 팀 (②)
- 대고객 AI는 별도 팀 **X스튜디오**. 원래 한 팀이었다가 올해 분리. 재통합 논의도 있음 (①②)
- WM 부문 **인사이트랩**(고객 데이터 분석)에서도 AI 활용 (②, JD)
- 구성원 배경 (③②):
  - 팀장: 타 대기업 개발자 출신 → 백엔드 지식 기대치 높음 (①)
  - 부장: 금융 쪽 백그라운드
  - IT 백그라운드 경력 1명, 그 외 금융권 경력자
  - 신입 2명: 작년 1명(인문+AI 복수전공, 챗봇 기획 인턴) / 올해 1명(전자공학+금융공학 석사)
  - 실질 관리 인력은 "두 분 정도"라는 언급 → 소규모 (③)
- 신생 팀. 상위자는 배경 다양, **신규 입사자는 모두 AI 역량 보유** (③)

### 1-4. 업무 프로세스 (자소서·면접에서 그대로 쓸 수 있는 구조)
1. **니즈 수집** — 부서별 업무연락. 자체 발굴과 타 부서 요청 둘 다, 점차 확대 단계 (①③)
2. **미팅** — 아무것도 없는 상태에서 시작. 부트캠프 프로젝트 기획과 동일 (①)
3. **데이터·업무 검토** — 현업 데이터 받아 검토, 수정 방향 제안 (①)
4. **요건 정의·문서화** — 와이어프레임(화면까지 그려주는 게 최선), 필수 기능, **왜 만드는지**(개발팀 설득). 프레임워크(LangChain 등)는 지정하지 않음 → 개발팀 결정 (①)
5. **다우기술 전달** — 개발 지식 없는 현업 ↔ 현업 지식 없는 개발팀 사이 "통역". A를 B로 잘못 전달하면 AIX 책임 (①)
6. **검토·운영** — 결과물 검토, 배포 후 사용량·에러 확인 (①)

**하지 않는 것**: AI 모델 개발·연구 (다우기술도 모델을 가져다 쓸 뿐). 단, 연구 경험은 좋게 봄 (③). PoC(시연용 소규모 결과물)는 직접 개발 (①)

### 1-5. 하루 일과와 팀 문화
- 출근 → 담당 사내 AI 프로젝트 전일 사용량·에러 확인 → 개발팀 주간 소통 정리 → **현업용 문서 작업(비중 최대)** → 회의. 와이어프레임은 초기 기획 때만. 툴은 사내 워드, 외부 AI로 초안 후 절차 거쳐 반입 (①)
- 협업 범위: 시작 단계라 타 부서 대규모 협업은 적고 **주로 다우기술 AI·에이전트 개발자와 소통** (③)
- 다우기술과의 마찰 처리법: 결국 **내가 이 서비스를 더 잘 이해하고 내가 맞다고 주장**해야 함. 정 안 되면 다투기도 하고 팀장에게 올림. 개발자들은 개발 모르는 현업과 얘기하기 싫어하지만 ICT·AIX는 IT 역량이 있어 "말이 통해서" 커뮤니케이션이 크게 어렵지 않음 (③) → 갈등·소통 면접 질문의 실제 배경
- 문화: 개발자 출신 다수, **개인주의적·독립적**, 터치 적음, **칼퇴** (7~8개월 근무 중 야근 총 1시간). 회사 전체는 "일하는 걸 장려하는" 분위기라 AIX는 예외적으로 여유 있음 (②③)
- 실패 허용: 사용률 저조한 서비스도 부정적으로 보지 않음. 시도 자체를 장려 (③)
- 사내 LLM 현실: 타 부서 실사용은 "보고서 문구 다듬기" 정도. AIX가 활용도를 묻고 다님. "외부 Claude Pro처럼 잘 됐으면" (③) → **활용도 제고가 팀의 고민**

## 2. 회사·업계 맥락 (지원동기·역질문 소재)

### 2-1. 회사 방향
- **사장(대표)이 가장 신경 쓰는 게 AI.** 관련 기사 다수. 매일 AI 강조 (②③)
- **리테일 강자 유지**가 핵심 전략. 리테일이 수익의 50~60%. 리테일 부서가 매일 신규 기획을 ICT에 검토 요청 (②③)
- 시장이 꺾이면 리테일이 무너지므로 **S&T·IB(M&A) 확장** 추진 중. 그런데 **그쪽에는 AI가 전혀 없음** → 전략적 공백 (②)
- 위에서 "토스 따라 하지 마"라고 하지만 신규 서비스를 계속 출시하고 AI도 많이 쓰는 분위기. ICT는 기존 시스템·사용자 영향 최소화 관점에서 보수적 검토 (③)
- 토큰증권(STO): 담당자만 지정, 현재 비활성 (③)

### 2-2. 금융권 AI의 제약 (반드시 알고 말해야 할 것)
- **망분리**가 최대 제약. 3개 망 (②):
  - 인터넷망: 네이버·구글 가능, 클라우드 업로드(구글드라이브·지메일 등) 차단
  - 업무망(내부망): 완전 인트라넷. 문서·결재
  - 중요단말망(보호망): 고객 데이터·DB 접근, 실제 개발·구축
- 무엇을 하려 해도 **컴플라이언스·법무 검토 → 금감원 확인** 절차 (②)
- 외부 AI(Claude·GPT)는 사내에서 사용 불가. **내부 구축 LLM** 사용, 성능은 외부보다 낮음. 외부 AI 결과물은 민감정보 제외 시 정해진 절차(메일 등)로 반입 가능 (①③)
- 리서치 자동화의 한계: 회사 이름 걸고 나가는 리포트라 **수치 검수·컴플라이언스 검토 필수** → 100% 자동화 불가, 검수자 1명 필수. AI는 "분기별 수치 브리핑" 수준, 애널리스트의 독창적 의견은 대체 불가 (②)

### 2-3. 키움의 AI 현황
- AI 리서치 리포트: **작년에 이미 구축**. 홈페이지 리서치 메뉴에서 확인 가능. 리서치 부문과 협업 (②)
- 챗봇 "키우Me"(추정 표기): 박인준 주임 지원 당시 진행 중이던 프로젝트 (①)
- 사내 LLM: 내부망용 구축·운영 중 (①③)
- AIX 외 AI 적용 사례: ICT 채널기획이 자체 진행한 검색 기능 AI 적용 등, 현업·ICT도 AI를 쓰고 있음 (③)
- AI 조직: AIX(사내) + X스튜디오(대고객) 두 팀 체제. 타사 대비 소규모 (②)
- 사내 AI 활용 주제는 대부분 MTS·리테일 관련 (②)
- **AI 리서치 자동화는 업계 표준화된 상태.** 대부분 증권사가 이미 하고 있고 키움도 작년에 했음 → 이 주제로는 "신기하다"는 인상을 주기 어렵고, 현직자는 프로젝트를 볼 때 **아이디어의 신선함**을 중요하게 봄 (②)

### 2-4. 타사 벤치마크 (②)
- **KB증권**: 기술적으로 가장 앞섬. 중요단말망(보호망)에 **Claude Code 도입** 진행. AWS Bedrock 기반, 방화벽·가드레일, 규제 통과 완료
- **미래에셋증권**: AI **부문**을 별도 신설 (부문 → 본부 → 팀, 대규모)
- 키움은 두 팀 체제로 상대적으로 작음 → "어디서 차별화할 수 있나"에 대한 자기 의견이 있으면 좋음

### 2-5. 개발·운영 구조 (③)
- 현업 기획 → ICT 검토 → **다우기술(모회사)** 개발. 사내에 "개발팀 개발자"는 없음
- ICT는 이슈·일정 관리 위주. 서버·트래픽 모니터링 시스템도 다우 구축, ICT가 보고 의사결정
- 이슈 관리 툴: 10년 넘은 Jira → 올해 **자체 개발 이슈관리 시스템** 전환. 모바일은 Redmine
- 미국 주식 야간 대응: ICT 24시간 모니터링 아님, 별도 인력 운영

## 3. 채용에서 보는 것 / 안 보는 것

### 3-1. 보는 것 (세 명 공통)
- **AI 관련 프로젝트 경험**: 개발이면 무엇을 개발했는지, 기획·디자인이면 어떤 AI 프로젝트에서 어떤 역할을 했는지 (①)
- 이런 경험이 있는 지원자가 **의외로 적음**. 금융회사 지원자는 경영·경제만 알고 IT를 모르는 경우가 많아 프로젝트 경험이 큰 차별점 (①)
- 부트캠프 프로젝트 참여 자체를 회사가 좋게 볼 것 (②)
- 대회는 **수상 여부보다 그 안에서 무엇을 했는지** (①)
- **망분리 환경에서 작업해본 경험**, 기본 데이터 분석 경험은 가점 요소 (②)
- 회사·팀의 최신 AI 동향 이해와 자기 경험의 연결 (①)
- AIX 팀장이 보는 것: **AI 역량 + 소통 능력** (③)
- **AI 에이전트를 직접 만들어본 경험**은 명시적으로 "좋다"는 반응 (③)
- **백엔드 경험은 희소 자원**: 팀 프로젝트마다 백엔드 인력이 "한 명 있거나 없거나" 수준이라 백엔드를 맡았다는 것 자체가 차별점 (①)
- 연구 경험(모델 개발 등)도 실무에서 쓰진 않지만 "미래 역량"으로 좋게 봄 (③)

### 3-2. 크게 안 보는 것
- 학력 등 정량 스펙 — 팀이 경력직 중심이라 정량 기준 자체가 애매 (①)
- **자격증**(빅데이터, 정보처리기사 등) — "크게 안 본다" (①). JD 우대사항에 "금융 및 디지털/IT 관련 자격증"이 있긴 하나 현업 시선은 이렇다
- 깊은 금융·주식 지식 — AIX 한정. 박인준 주임도 입사 전 주식 거래·MTS 경험 전무 (①)
- 증권 경험 — AIX·ICT·X스튜디오 합격자 대부분 없음. 있으면 로열티로 보일 뿐 (③)
- CS·IT 전공지식 — 면접에서 테스트하지 않음 (③)

### 3-3. 그래도 필요한 최소한
- 기본 금융 용어(여신/수신, MTS/HTS 등)와 **회사가 어떻게 돈을 버는지** (①)
- "직무만 보고 지원한 게 아니다"라는 관심도 표시 (①)
- 참고: 리테일·플랫폼(MTS) 직무는 반대로 주식·서비스 이해가 핵심, 리서치도 마찬가지 (①)

### 3-4. 전공·배경
- 이공계·AI 전공은 정량적 플러스 (③)
- 하지만 서류는 정량 통과하면 끝. **면접에서 같은 질문에 옆 사람보다 설득력 있게 답하는 사람**이 뽑힘 (③)
- 경영학 전공이라도 관련 경험 있으면 충분히 가능 — AIX 신입 사례(경영+AI 복수전공) (③)
- 은행·타 업권 AI 경험, 대고객 서비스 경험도 모두 OK (③)
- 중고신입 비중은 기수마다 다름. 팀이 원하면 OK (③)

### 3-5. 서류 필터링 구조
- 인사팀이 먼저 선별 → 현업 전달. 인사팀 기준은 현업도 모름 (①)
- 서류에 **깃허브 링크·포트폴리오 PDF 첨부 없음** → 자소서 텍스트로만 보여줘야 함 (①)

## 4. 자소서 전략

### 4-1. 제출 시점
- **빨리 내라.** 마감 후 일괄이 아니라 들어온 순서대로 읽음. 뒤로 갈수록 읽는 사람이 지치고, 신입 경험은 편차가 작아 비슷한 내용은 앞사람과 비교되어 묻힘 (①, 비공식)

### 4-2. 읽는 사람 = 극도로 바쁜 팀장
- 자소서를 보는 건 **서류 때 한 번, 면접 직전 한 번**이 끝 (③)
- 기술 용어 나열("AI 모델 어쩌고, 선형 분석 어쩌고") → **못 알아듣는다** (③)
- 구구절절 나열 X → **핵심을 쉽게, 간결한 소재로, "경험 → 얻은 역량"으로 연결** (③)
- 기본기: 맞춤법, 구성, 가독성. AI 툴로 다듬는 것 OK. 소제목은 읽는 사람 취향 (①)
- 단, 쓴 용어에 팀장이 꽂히면 **반드시 꼬리질문** → 자소서의 모든 용어는 설명 가능해야 함 (③)

### 4-3. 프로젝트 서술법
- 길이 제한 → **아이템·역할·수행 내용** 위주로 컴팩트하게. "왜 그런 결정을 했나"·인사이트는 **면접에서 구두로** (①)
- 회사·팀이 최근 AI로 무엇을 하려는지 조사해서 내 경험과 엮기. 단, 팀이 찾는 사람과 실제로 다르면 겉만 비슷해 보여도 소용없음 (①)
- "개발 잘한다"가 아니라 **"개발·기획 경험이 있어서 개발자와 말이 통하고 현업 요건을 문서로 정리할 수 있다"** (③)
- 기술 vs 도메인 중 무엇을 강조? → **자신 있는 것, 면접에서 잘 말할 수 있는 것** (③)
- **어떤 프로젝트를 메인으로 쓸지의 기준**: 면접에서 옆 지원자와 같은 질문을 돌아가며 받게 되므로, **"옆 사람보다 내가 더 잘 말할 수 있고 꼬리질문에 끝까지 답할 수 있는" 프로젝트**를 고를 것. 우선순위 감각: 인턴·기업 협업 프로젝트 > 학부 개인 과제. 가장 얻은 게 많은 프로젝트가 보통 정답 (③)

### 4-4. 경험 배분
- **한 경험에 몰아서 쓰지 말 것.** 김재헌 사원 본인 반성: 큰 프로젝트 하나 위주로 쓰고 전공은 한 번만 언급 → 균형이 아쉬웠다 (②)
- 공백기·비정형 경험은 "회사 입장에서 어떻게 보일지" 의식해서 프레이밍 (②)

### 4-5. 추천 아이템
- **갈등·소통 오류 해결 경험**: 팀 프로젝트에 진심이면 반드시 의견 차이가 생기고, 이를 해결한 경험이 좋은 소재. 결과물보다 "그 과정에서 무엇을 느꼈나"가 중요. 소통·문제해결·갈등해결 역량은 실무에서 실제로 가장 많이 쓰임 (①)
- **입사 후 포부** 재료: 사내 LLM 활용도 제고·기능 개선, AI 거버넌스·가이드라인 수립 참여, 리테일 외 부문(S&T·IB·운용 지원) AI 도입 (②③)

## 5. 면접 전략

### 5-1. 전형 구조와 변동 이력 (⚠ 매 기수 바뀜)
| 기수 | 1차 | 2차 | 기타 | 출처 |
|---|---|---|---|---|
| ICT 현직자 기수 | 팀장급 실무 면접 | 동료 면접 (바로 위 사수 대리 참석, 인성 위주) | AI 면접 없음. 영어 면접 선택 | ③ |
| 김재헌·박인준 기수 | 팀장급(부장·이사) | 실무진(차장·과장·대리) + **사이드 AI활용능력평가면접** | 최종은 임원 | ② |
| 올해 (전언) | ? | **PT 면접으로 바뀌었다고 들음** | 확정 아님 | ③ |
- JD: 서류 → 1차 → 2차 → 최종 → 채용검진. 필기·인적성 없음
- **결론**: 안내 메일을 최우선으로. AI 면접·PT 둘 다 가능성 열어두기

### 5-2. AI활용능력평가면접 (②)
- 2차와 함께 사이드로 진행. **0~3점 가점**. 면접관은 AIX 팀원 전원(팀장·부장·박인준 주임·김재헌 사원 등). 올해도 있을 가능성 높다고 함
- 분위기: "진짜 편하게 보면 된다". 질문: 뭘 해봤냐 → 어떻게 했냐 → 뭘 썼냐 → 기술 베이스가 어느 정도냐 (**꼬리질문으로 깊이 파고듦**)
- 채점 기준 (작년 약 110명, 실제 채점표 기준):

| 점수 | 기준 |
|---|---|
| 0점 | 챗봇을 그냥 사용만 해봤다 (거의 안 줌) |
| 1점 | 챗봇으로 스크립트를 짜봤다 |
| 2점 | 파이썬 스크립트로 시스템 구축, DB 구축, RAG 기반 챗봇 구축 등 |
| 3점 | 그 이상의 프로젝트 경험 (110명 중 **8명**) |

- 3점 코멘트 예: "실질적으로 지금 바로 투입할 수 있는 수준". 가산 요소: 망분리 환경 작업 경험, 데이터 분석, AI 프로젝트
- 부트캠프 프로젝트 수준이면 "말만 잘하면 최소 2~3점"
- **AIX 팀장이 여기서 마음에 든 사람을 다른 부문 합격자 중에서도 데려간다.** 김재헌 사원은 S&T로 서류·면접 전부 진행 → AI 면접에서 팀장 눈에 띔 → 합격 1시간 전 AIX 배치. 즉 이 면접이 사실상 AIX 선발의 핵심

### 5-3. 1차 (팀장급) 면접 (③①)
- CS·IT 전공지식 테스트 없음. 자소서 기반
- 질문 **5~6개 + 각 1개 정도 꼬리질문**. **말 너무 길게 하지 말 것**
- 질문 예측은 거의 불가능 → 공통 질문 대비 + 자신감
- 실제 질문 패턴 (ICT 현직자 사례):
  1. 자소서 문구 하나를 잡음 ("실시간 데이터 통신 트래픽을 이해했다") → "그게 뭐냐?"
  2. → 증권사 상황에 적용: "증권사에서 트래픽이 많이 발생하면? 어떤 상황에서?" (답: 공모주 청약)
  3. 다른 증권사 서비스 써봤나? 우리 앱(영웅문) 써봤나?
  4. 우리 앱 개선점?
  5. AI를 어떻게 쓸 것인가?
  6. 마지막 어필
- **패턴: 자소서 문구 → 개념 확인 → 키움/증권 상황 적용 → 우리 서비스 사용 경험 → AI 활용 의견 → 마무리**
- 금융 질문은 많지 않음. 직무 역량(프로젝트) 중심 (①)

### 5-4. 2차 (실무진) 면접
- 역량은 기본이고 **"이 사람이 내 후배로 왔을 때 말이 통할까"** = 커뮤니케이션 (③)
- 서류에 못 담은 Why·인사이트를 여기서 풀기 (①)
- 커피챗·설명회에서 만난 현직자가 면접관일 수 있음 (①②③)

### 5-5. 가장 많이 받는 질문: "여기 와서 뭐 하고 싶냐" (①)
- 스펙 나열보다 이걸 **명확하게** 답하는 사람이 기억에 남음
- 부서 방향성과 정확히 일치할 필요는 없음 → **산업·직무 이해도 + 적극성**을 총체적으로 보는 질문
- 준비 재료: 1-2, 1-5, 2-1~2-4 참고
- **세트로 나올 질문: "AI를 잘 다루면 어느 산업·어느 기업이든 갈 수 있는데, 왜 키움·왜 증권인가?"** 설명회에서 지나가던 임원급이 AIX 지원자들에게 직접 던진 말. (③) AIX는 금융 지식을 크게 요구하지 않는 대신 이 질문에 대한 답이 비어 있으면 약점이 됨 → 2장(회사 방향·AI 제약·현황)을 재료로 준비

### 5-6. 영어 면접 (③)
- **설명회 공식 안내: 영어 면접은 선택적으로 추가 수행 가능.** ICT 현직자도 봤음. AIX·ICT는 영어 쓸 일 없음. 가벼운 대화 수준("끝나고 뭐 할 거냐"). 플러스인지 불확실. 자신 있으면 응시

### 5-7. 배치·합격 구조
- 최종 면접 **4명 중 3명 합격** → 각 부서 배치. 옆 지원자와 제로섬 아님. 역량 있으면 유관 부서(AIX↔ICT↔X스튜디오↔플랫폼)로 배치될 수 있음 (③)
- 지원 직무로 뽑히면 거의 그대로 배치. 틀어지면 인사팀이 **먼저 연락해 의향을 물음** (③)
- 부서 배치는 마지막까지 바뀔 수 있음 (②)
- 입사 후 OJT 없음. 2주 동기 연수 후 바로 팀 배치, 업무하면서 배움 (②)

### 5-8. 태도
- **겸손하지만 씩씩하게, 자신감 있게** (③)
- 인성 질문부터 자소서 기반 질문까지 전부 준비 (③)
- 면접은 볼수록 는다 (③)

## 6. 일반 준비 체크리스트 (개인 경험 문서와 결합 예정)

### 조사·학습
- [ ] 영웅문S# 직접 사용 + 타사 MTS 1~2개 비교 + 개선점 메모 + "여기에 AI를 어떻게 쓸지"
- [ ] 키움 홈페이지 리서치 메뉴에서 **AI 리서치 리포트** 확인
- [ ] 대표의 AI 강조 관련 기사 1~2개
- [ ] 기본 증권 용어: 여신/수신, MTS/HTS, 증권사 수익 구조(브로커리지·IB·S&T·WM), 리테일/리서치/컴플라이언스 역할
- [ ] 망분리 3망 구조, 금융권 생성형 AI 규제 흐름 (금감원·망분리 완화)
- [ ] 타사 동향 한 줄씩: KB증권(보호망 Claude Code·Bedrock), 미래에셋(AI 부문)
- [ ] 증권사 특유 상황(공모주 청약 트래픽, 장 시작·마감, 야간 미국주식)을 AI 업무효율화 관점에서 생각

### 자소서
- [ ] 문항 확인 즉시 소재 배치, **마감 전 최대한 빨리 제출**
- [ ] 제출 전 특수문자·`<` 기호 점검, 임시저장 후 확인 페이지에서 줄 누락 여부 확인 (0-1 FAQ)
- [ ] 비개발자가 읽어도 이해되는 문장으로. 기술 용어는 필요한 것만, 전부 설명 가능하게
- [ ] 아이템·역할·수행 위주. Why는 면접용으로 따로 정리
- [ ] 경험을 여러 축으로 배분
- [ ] 갈등·소통 해결 아이템 1개 확보
- [ ] 입사 후 포부: 사내 LLM 활용도·거버넌스·리테일 외 AI 중 연결

### 면접
- [ ] AI 면접 대비: 프로젝트를 3단계(개요 → 아키텍처 → 구현 디테일·도구)로 설명. 직접 짠 것 / AI 도구로 짠 것 솔직히 구분
- [ ] 1차 대비: 자소서 문구마다 "그게 뭐냐 → 키움에서는?" 시뮬레이션
- [ ] PT 대비: "문제 정의 → 제약(망분리·컴플라이언스) → 해결 → 검증" 구조 연습
- [ ] "여기 와서 뭐 하고 싶냐" 답변 1~2개 구체화
- [ ] "AI 잘하면 어디든 갈 수 있는데 왜 키움·왜 증권인가" 답변 준비
- [ ] 메인 프로젝트 선정: 옆 사람보다 잘 말할 수 있고 꼬리질문 끝까지 받을 수 있는 것으로
- [ ] 갈등 사례 STAR 정리
- [ ] 답변 짧고 명확하게. 겸손하지만 씩씩하게
- [ ] 커피챗·설명회에서 말한 관심사와 자소서·면접 내용 일관성 점검
