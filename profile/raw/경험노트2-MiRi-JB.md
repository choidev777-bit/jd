## 3. 기획 스토리 (핵심 소재)

### 3-1. 주제 선택 — 경쟁 구도를 먼저 봤다
**F** 회의로 처음부터 자유주제로 결정. 이유: 지정주제 3개에는 팀이 몰려 같은 문제 안에서 상대비교되고, 자유주제는 문제 정의 자체로 평가받을 수 있어 **수상 확률이 더 높다**고 판단.
→ 면접 표현은 확률로 유지: "지정주제는 안 된다"가 아니라 "자유주제가 수상 확률이 높다고 봤다". 1위가 지정주제(준법)였다는 사실과 충돌하지 않음. 결과(13팀 중 2위)가 판단을 뒷받침.
→ DAY-JA-VIEW에서 토스의 "실시간" 포지셔닝을 보고 반대로 "과거"로 간 것과 같은 사고 패턴. **"심사자·경쟁자가 어떻게 비교할지를 먼저 보고 빈 자리를 찾는다"**로 두 프로젝트를 묶을 수 있음.

### 3-2. 아이디어 ① 외국인 금융 AI → 현장 인터뷰 후 폐기
**F** JB 회장 메시지(신년·경영전략)에서 외국인 금융 집중을 확인 → 외국인 금융을 돕는 AI 에이전트 기획 → **전북은행 동대문 외국인금융센터에 직접 찾아가 인터뷰** → 이미 시스템이 잘 구축돼 있다고 판단 → 폐기.

**뉴스로 확인된 배경**: 김기홍 회장은 2026년 1차 경영전략회의에서 외국인·전략 여신 확대와 IB 강화를 주요 목표로 제시. JB금융 3사 외국인 대출 잔액은 2026.3 1조 원 돌파, 시장 점유율 70% 이상. 전북은행은 2016년부터 외국인 전용 채널을 만들고 약 200명의 외국인 상담사·10개국 언어 콜센터를 운영.
→ **"회장이 강조한 영역이라 매력적으로 보였지만, 현장에 가서 확인하고 접었다."** 현장 검증으로 아이디어를 폐기한 장면은 DAY-JA-VIEW에 없는 소재. 실제로 JB가 국내에서 가장 앞선 영역이라 AI를 얹어도 새롭지 않았을 것 — 판단이 정확했음.

### 3-3. 아이디어 ② AICC(전화상담 대기 불만) → 진부해서 폐기
**F** "몇 번을 눌러주세요" 대기가 화난다는 팀 의견에서 AICC 기획 → 너무 진부하다고 판단 → 폐기.

### 3-4. 재정의 — JB의 실제 문제에서 출발
**F** 며칠 밤새 고민. 기준: **좋은 서비스는 설명을 듣자마자 "와 이거 진짜 필요하네"가 나와야 한다. 곰곰이 생각해야 좋아 보이면 좋은 서비스가 아니다.** → JB금융그룹의 실제 문제를 풀면 좋은 평가를 받는다 → 조사 → 전북은행은 실적은 좋은데 기업대출·자영업자 연체가 많다 → **"자영업자가 은행 돈으로 가게를 운영하면, 은행은 그 돈으로 가게가 잘 운영되는지 확인해볼 필요가 있다"** → 대출 이후 관찰·조기경보 서비스 기획.

**뉴스로 확인된 배경**
- 실적: JB금융 2025년 당기순이익 7,104억 원 역대 최대, PBR 1배 돌파. ROE 13%대는 시중은행 포함 최상위권
- 연체: 2026년 1분기 지방은행 연체율 중 전북은행 1.65%로 최고. 2025년 1분기 기업대출 연체율도 전북은행 1.53%로 지방은행 1위. 지방은행 차주는 지역 중소기업·개인사업자 중심, 중저신용자 연체율 5.38%(5대 은행의 5배)
- 업종: 2026년 상반기 말 전북은행 **숙박·음식업 연체율 3.54%**, 제조업 2.04%. 금감원은 지방은행을 차주·업종별로 세분화해 모니터링 주기를 단축 중
→ MiRi가 **전북·전남 요식업**을 타깃으로 잡은 것은 최약 업종을 정확히 짚은 것. 금감원이 은행에 요구하는 방향(차주별 세분화 모니터링)과도 일치.

## 5. 기술 요약 (AI 면접용)

### 5-1. 설계 원칙 (연준님 표현)
> **판단은 ML(LightGBM + 룰)이 하고, LLM은 그 결과를 받아 설명만 한다. ML을 AI 에이전트의 tool로 붙인 구조.**

→ DAY-JA-VIEW("서버가 조회·계산, LLM은 문장만")와 동일한 원칙이 두 프로젝트에서 반복됨. 금융권 AI의 수치 정확성·컴플라이언스 문제(② 김재헌)에 대한 답. 1위 FinProof도 "AI는 최종 승인자가 아니다, 심의자가 결정"이 핵심 원칙이었음 → 같은 방향.

### 5-2. 데이터 (정확히 말해야 하는 부분)
- **실데이터**: 소상공인시장진흥공단(소진공) 공식 API로 전북·전남 요식업 업소 **65,063곳 전수 수집** → 상권 밀집도 피처 실측
- **proxy**: 서울 상권분석서비스 실데이터(2021~2025)에서 매출 분포 모수를 측정해 전북·전남 합성 차주에 이식
- **학습 데이터는 합성 차주 5,000명** (전북은행 실차주 데이터 접근 불가)
- 리뷰 텍스트 → LLM이 이진 신호 5종 추출 → 월별 집계해 정형 피처로 투입 (리뷰 데이터는 합성 208건 PoC)
→ 자소서에 "리뷰를 LLM으로 평가해 ML에 넣었다"고만 쓰면 실데이터로 오해될 수 있음. "실데이터 접근이 불가능한 조건에서 공공 API 실측 + 실데이터 proxy + 합성으로 파이프라인을 검증했다"고 정확히 쓰고, 한계를 먼저 말하는 게 금융권 면접에서 유리.

### 5-3. 모델·룰
- LightGBM 3·6·12개월 부실확률(60일+ 연체 기준) → triage A~D
- 피처 28개: 금융행태(계좌평잔·고정비미납·연체이력) + 대안데이터(상권대비매출·밀집도·배달앱 평점 변화·이직) + 리뷰 신호 5종
- SHAP으로 차주별 위험 사유 산출 → 위기유형 6종은 SHAP 결과에 **룰**로 매핑 (LLM 아님)
- 지원상품 매칭은 자격 필터 → 등급 게이트 → 자금용도 정렬의 **결정적 룰**. LLM은 추천 사유 문장만

### 5-4. 백엔드·에이전트 (연준님 담당)
- FastAPI 허브. pydantic-ai(Claude) 에이전트가 모델 결정값을 tool로 받아 서술. LLM 키 없어도 결정적 폴백으로 동작
- 거버넌스 모듈 존재: 고객 동의 확인(철회 시 차단), 감사 로그, PII 마스킹, 고객 응답에서 점수·등급 어휘 차단, 판단 정책 변경 이력 기록
- RAG(bge-m3 로컬 임베딩)는 제도 Q&A·추천 근거 문장에만 사용, 매칭 판단에는 불개입
- 개입 후 점수 변화 추적 → 재학습 파이프라인(개입받은 차주는 학습 제외)

### 5-5. 스택·배포
Python 3.11·uv / LightGBM·SHAP·scikit-learn / FastAPI·pydantic-ai·SQLite / React·TypeScript·Vite(PWA) / Vercel(프론트 2개) + Railway(백엔드 Docker) / 테스트 35파일 / 예선 제출물 기준으로 개발 (기능명세서 → 구현)

## 6. 1위와의 비교 (이주환 팀장 질문 대응)

**F** 이주환 AIX 팀장 질문 "온톨로지 만들어본 경험 있나?" → 답 "한 달 전 JB 해커톤 2위, 1위가 온톨로지를 써서 공부했다."

**1위 FinProof의 실제 구조**: OCR → RAG(pgvector) → 도메인별 서브 에이전트 6개 → 근거 인용이 붙은 이슈 생성 → 심의자 최종 판단. 온톨로지는 그중 한 모듈 — 캄보디아·베트남·미얀마·중국·태국 5개국의 민감 사건·왕실·종교·국가상징·정치 시위 상징을 노드·엣지·리스크 룰로 정리한 **지식 그래프**로, 다국어 홍보물에서 "민감 사건 날짜 + 금융 혜택 이벤트" 같은 조합을 탐지.

→ **다듬은 답**: "1위 팀이 다국어 홍보물의 사회적 맥락 리스크를 잡기 위해 국가별 민감 사건·상징을 지식 그래프로 구조화한 걸 봤습니다. 텍스트 검색으로는 못 잡는 관계를 구조로 잡는다는 게 인상적이어서 온톨로지를 공부했고, 다음 프로젝트에서 '소재 1개에 테마 9개가 반응하는' 관계 문제에 적용했습니다."
→ 왜 2위였는지는 본인도 모름. 추정 대신 "1위와 저희의 공통점은 AI 결정 범위를 제한하고 사람이 최종 판단하게 한 것, 차이는 1위가 근거 구조(법령·사례 인용, 지식 그래프)를 더 깊게 만든 것"으로 답하는 것이 안전.

| E. 실데이터 불가 조건 대응 | 공공 API 실측 + proxy + 합성으로 파이프라인 검증, 한계 명시 | ② 망분리 환경에서 데이터 제약을 다루는 감각 |
| F. 역할 분리 팀 운영 | ML은 팀원, 본인은 기획·백엔드 | DAY-JA-VIEW 팀워크 약점 보완 |
| G. 학습 속도 | 1위 분석 → 온톨로지 학습 → 다음 프로젝트 1위 | AIX 팀장 질문에 직접 답한 소재 |

## 8. 예상 꼬리질문

- **왜 자유주제?** → 3-1 확률 논리
- **외국인 금융은 왜 접었나?** → 현장 인터뷰, 이미 최고 수준 구축(콜센터 200명·10개국어, 점유율 70%)
- **합성 데이터로 뭘 증명할 수 있나?** → 파이프라인·설명가능성·개입 흐름 검증. 실전 예측력 증명은 아님을 먼저 말하고, 실데이터 전환 시 모델이 재추정된다는 구조 설명
- **LLM은 어디에 쓰였나?** → 리뷰 → 이진 신호 추출(입력단), 결과 설명·상담 대본(출력단). 점수·등급·매칭 판단에는 불개입
- **은행이 소상공인 가게를 관찰하는 게 과도하지 않나?** → 고객 동의 기반, 고객 화면에는 점수 미노출·코칭 톤, 목적은 부실 전 지원 연결. 금감원이 은행에 차주별 모니터링 강화를 요구하는 방향
- **1위와 차이?** → 6장
- **키움에 적용하면?** → 대출 차주 대신 고객·계좌·거래 데이터 기반 이상 신호 조기경보, 또는 사내 업무에서 "판단은 룰·데이터, LLM은 설명" 원칙 적용
