## 3. 맵타민 (Maptamin.com) — 2025.12~2026.04

### 3-1. 사실
- **동기**: AI 활용 능력을 증명하는 가장 확실한 방법은 사람들이 돈을 내고 쓰는 서비스를 만드는 것. 자주 가던 음식점 사장님의 "지역 마케팅이 너무 어렵다"에서 출발
- **문제**: 기존 네이버 순위 추적 서비스(애드랭크·캐치랭크 등)는 "홍대 카페 38위" 같은 숫자 하나만 제공. 실제 네이버 지도는 검색자 GPS에 따라 순위가 완전히 달라짐(가게 앞 3위, 두 블록 건너 40위 밖). 북미에는 그리드 맵 서비스가 있지만 한국엔 없었음
- **해법**: 상권 내 수십 개 좌표에서 업종 키워드 순위를 동시 측정 → 지도 위 초록/노랑/빨강 → "초록불을 늘리세요" 하나의 목표. 마케팅 모르는 사장님도 바로 사용
- **결과**: 출시 1개월 내 **결제 사용자 약 120명**
- **종료**: 키움 디지털 아카데미 지원 조건(사업자 불가) → 폐업. "돈이 목적이 아니라 실제 구매되는 서비스라는 증명이 목적이었기 때문에 바로 접었다"

### 3-2. 기술 — 좌표당 비용 50원 → 1.6원 (약 1/30)
- 구글 순위는 DataForSEO 유료 API로 해결. 네이버는 위치 기반 검색 API가 없어 **수집 구조를 직접 설계**
- 첫 버전: GitHub Actions에서 Playwright로 브라우저를 띄워 지도 열기 → 좌표 입력 → 확대 → 검색 → 목록 읽기를 좌표마다 반복. 화면 렌더링에 필요한 이미지·타일·폰트·JS를 전부 내려받아 **좌표당 약 50원**. 25좌표 측정 1회에 수천 원 → 판매 불가
- 접근 전환: **"사람 인터랙션을 모사하지 말고, 서버가 이미 직렬화해 내려주는 상태를 그대로 받자"**
  1. UI 조작 전면 제거 — 좌표·키워드를 URL(`pcmap.place.naver.com/place/list?query=&x=&y=&display=70`)에 인코딩, 문서 1회 요청
  2. stylesheet/script/image/media/font 전량 abort — 필요한 건 HTML 문서 하나
  3. DOM 파싱 → SSR 하이드레이션 상태 파싱. Apollo Client 정규화 캐시(`window.__APOLLO_STATE__`)를 직접 읽음. 렌더 대기 제거, 셀렉터 변경 내성. 실패 시 정규식 폴백
  4. 정규화 캐시를 순서 보존해 resolve. 광고(adDescription) 제외 후 순위 부여. "새로 오픈" 섹션은 별도 쿼리라 자동 배제
  5. `display=70`으로 페이지네이션 제거 — 1요청 70건
  6. 브라우저·세션 재사용 — 배치당 Chromium 1개, 태스크마다 탭만 생성·파기
  7. 실행 환경 GitHub Actions → 상시 기동 Oracle Cloud VM 워커. 웹은 작업 요청만, 수집은 워커 전담
- **측정**: 태스크별 데이터 사용량과 소요시간을 로그로 계측 → 단가 변화를 추정이 아니라 측정으로 확인

### 3-3. 프레이밍
→ **AI 활용 소재로서**: "AI를 잘 다룬다"를 증명하기 위해 실제 유료 사용자를 만들었다는 접근 자체가 차별점. 김재헌 사원 채점표 기준(2점: 시스템 구축, 3점: 그 이상)에서 "혼자 설계·구축·운영·과금까지 한 서비스"는 3점 구간의 근거
→ **문제해결 소재로서**: 비용이 사업성을 막는 벽 → 절약(캐시·이미지 대체)으로는 한계 → 접근 자체를 바꿔 1/30 → 측정으로 검증. "구조를 바꿔 문제를 푼다"는 사례
→ **소상공인 도메인**: 맵타민(광고 효율) → MiRi(대안신용). 사장님 인터뷰에서 시작한 두 서비스
→ **AIX 연결**: 페인포인트를 현장(사장님)에서 듣고 → 기존 서비스 조사 → 빈 자리 발견 → 만들고 → 사용자 반응으로 검증. AIX의 니즈 수집 → 검토 → 구현 → 사용량 확인 흐름과 동일

### 3-4. ⚠ 리스크와 대응
- **크롤링·약관**: 원문 서술에 "네이버가 반복 접속을 차단하기 때문에 거주지 프록시(Bright Data)로 IP를 바꿔가며 접속"이 있음. 증권사 면접관은 "차단 우회"로 읽을 수 있음
  - 자소서·면접 서술에서 **프록시·IP 변경·차단 우회 표현 제거**. 기술 이야기는 "공개 검색 결과 페이지를 렌더링 없이 최소 요청으로 받아 비용을 1/30로 줄이고, 계측으로 확인했다"에 집중
  - "약관 위반 아니냐"는 질문 대비 답 ⚠ 준비 필요: 공개 페이지·비로그인·개인정보 미수집·요청 최소화 같은 사실 + 서비스 종료 상태. 방어적이 아니라 "그 경계를 알고 있었다"는 톤
- **창업 이력 재차**: 사업자 등록·유료 결제 = 사업. 2장의 30초 답과 "아카데미 위해 폐업" 사실로 대응. 오히려 이 폐업이 이탈 우려의 반증
- **현재 상태**: 2026.04 종료(사업자 폐업). 면접에서 "지금도 운영하냐"가 오면 "아카데미 지원 조건 때문에 접었다"로 답

  - 구성 의미: 실제 사용자(키움) / 업계 공통인지 교차 확인(NH) / 검수·책임을 지는 관리자 시각(전 센터장). "쓰는 사람과 책임지는 사람을 모두 물었다"
  - **섭외**: 애널리스트 2명은 **리멤버에서 직접 연락해 미팅**(콜드 컨택). 전 센터장은 가족 소개
  - ⚠ 형식(대면·전화)·시간, 각자의 핵심 발언(특히 전 센터장의 검수·책임 관점, 키움 애널리스트의 내부 AI 리포트 언급 여부)
  1. 어닝리뷰 리포트를 쓸 때 이전 분기 리포트를 그대로 가져다 쓰느라 **이전 분기의 흔적이 남는다**
  2. 가설을 세우고 리포트를 쓰는데 **가설에 맞는 자료를 찾는 게 힘들다**
- 이 둘을 해결하는 자동화 시스템. 하네스로 전체 프로세스를 관리하고, **AI가 찾은 데이터를 다른 AI가 검증하는 구조**도 구현

**⚠ 섭외 경로 답변 주의**: 전 센터장 소개자(부친, 금융감독원 재직)는 **자소서·면접에서 언급하지 않음**. 채용절차법상 면접관은 부모 직업을 물을 수 없고, 지원자가 먼저 말하면 감독기관과의 관계라는 점에서 불필요한 해석(청탁·이해관계)을 부를 수 있음. 물으면 "가족 지인 소개로 만났다"까지만. 섭외 이야기의 중심은 **리멤버로 현직 애널리스트에게 직접 연락해 미팅을 잡았다**는 쪽에 둠 — AIX에서 현업을 찾아가는 방식과 같고, 연준님이 반복할 수 있는 행동임

### 4-2. 레포에서 확인되는 구조 (참고용, 자소서엔 필요한 만큼만)
- 흐름: 프로젝트 설정 → **이전 분기 Review PDF + 분석 Excel 업로드** → 투자의견·조사 질문(가설) → 자료 수집 계획 → 조사 결과·Excel 검증 → Excel 롤포워드·PER 밸류에이션 → 페이지 내용 설정 → 초안 편집·검증·내보내기
- **검증 원칙** (기술결정 문서): 모든 핵심 숫자와 보고서 주장은 원문 위치 또는 Excel 계산 경로를 가져야 한다. **Validation Agent는 Research Agent의 추론을 신뢰하지 않고** 공식 URL·문서 ID·페이지 위치·정규화 값을 받아 원문을 독립적으로 다시 확인
- Agent 출력은 제안이며 Evidence 검증·결정적 계산·사용자 승인을 대체하지 않음. Excel 실제값은 등록 규칙과 공식 구조화 원천(OpenDART·KRX·ECOS)으로 deterministic 수집
- 원본 불변, 새 version, 상위 변경 시 하위 산출물 `stale`/`revalidation_required`
- 스택: Next.js 모듈러 모놀리스, PostgreSQL, MinIO, **Temporal**(장시간 작업 재개), PDF worker(PDFium·OpenCV 시각 검증), Excel worker(.NET ClosedXML), LLM worker(PydanticAI), 외부 수집은 allowlist worker만

### 4-3. 프레이밍
→ **AIX와 가장 가까운 프로젝트.** ① 박인준의 AIX 프로세스(니즈 수집 → 현업 미팅 → 데이터 검토 → 요건 정의 → 구현 → 검토)를 그대로 밟았음: 애널리스트 인터뷰 → 페인포인트 2개 → 이전 분기 산출물을 입력으로 받는 구조 설계 → 검증 에이전트
→ ② 김재헌 피드백 활용: "페인포인트 현실적으로 잘 잡았다", "리서치 자동화의 병목은 검수·컴플라이언스" → REFLO는 처음부터 검증 에이전트와 원문 추적을 넣었으니 그 병목을 겨냥한 설계였다고 말할 수 있음. 단 "키움도 작년에 AI 리서치를 했다"는 걸 알고 있다고 먼저 말할 것
→ **"판단은 검증 가능한 것에, LLM은 해석에"** 원칙이 여기서도 반복 (MiRi·DAY-JA-VIEW와 동일). 세 프로젝트 공통 원칙으로 묶기
→ **인터뷰 소재 활용법**: "4명"이 아니라 **"쓰는 쪽(키움·NH 현직) · 운영했던 쪽(대신 전 센터장) · 읽는 쪽(운용사)"**으로 말할 것. 두 증권사 현직을 물었으니 "한 회사의 특수 사정이 아니라 업계 공통 문제"라고 말할 수 있음. 키움 현직 애널리스트 인터뷰는 "키움 리서치 업무를 내부자에게 들었다"는 의미 → 김재헌 "키움도 작년에 AI 리서치를 했다"와 연결해 "자동화 도입 후에도 남는 문제(검수·전 분기 흔적)를 겨냥했다"로. 전 리서치센터장 인터뷰는 "리포트가 회사 이름으로 나가는 무게" → 검증 에이전트를 넣은 이유로 연결
→ 지원동기·직무이해 문항에서 **DAY-JA-VIEW 뒤에 붙는 다리**로 사용. "리서치 업무를 자동화해봤고, 그 경험에서 사내 업무 자동화의 진짜 병목(검수·현업 신뢰)을 알게 됐다 → AIX에서 하고 싶은 것"으로 연결. 대표 프로젝트 자리는 심사위원이 직접 본 DAY-JA-VIEW에 둠

### 4-4. ⚠ 확인 필요
- 기간(정확한 주수)
- 애널리스트 인터뷰 섭외 경로, 각 인터뷰에서 물은 것 (꼬리질문 대비)

## 6. 소재 배분 (② "한 경험에 몰아 쓰지 말 것")

**원칙**: 자소서를 읽을 사람(AIX 팀장·팀원)은 최종 프로젝트 심사위원으로 **DAY-JA-VIEW를 직접 봤다**. 이 인지도는 다른 지원자가 가질 수 없는 이점이므로 DAY-JA-VIEW를 대표 프로젝트로 가장 먼저 세운다. REFLO는 "왜 사내 업무 AI인가"를 잇는 다리로만 쓴다.

| 문항 유형 | 메인 소재 | 보조 |
|---|---|---|
| 대표 경험 · AI·기술 역량 (AI 면접 포함) | **DAY-JA-VIEW** — "최종 프로젝트 1위" 명시. AI 작업 거버넌스 7단계, 정답지 검증 루프, Ragas | 맵타민 비용 1/30 |
| 지원동기 · 직무이해 · 입사 후 포부 | DAY-JA-VIEW를 만든 사람이 **왜 대고객이 아니라 사내 업무(AIX)인가** → **REFLO** 경험으로 연결: 애널리스트 인터뷰 → 리서치 업무 자동화 → 진짜 병목(검수·현업 신뢰)을 알게 됨 → 사내 LLM 활용도·거버넌스 포부 | 2017 영웅문 접점 한 줄 |
| 문제해결 · 도전 | **MiRi** (현장 검증 후 폐기 → 데이터로 재정의 → 523팀 중 2위) 또는 **맵타민** (구조 전환으로 1/30) | |
| 협업 · 소통 | MiRi 역할 분리 팀 운영 + DAY-JA-VIEW 작업 분해·위임 + REFLO 현업 인터뷰 | ⚠ 갈등 에피소드 없음 → "비개발자·현업과 요건을 맞추는" 소통으로 대체. DAY-JA-VIEW 팀워크 6점을 의식해 협업 문항은 MiRi 중심 |
| 성장과정 · 가치관 | 2017 기획만 → 2025 직접 만들어 판매 → 2026 조직 안에서 검증 | 맵타민 폐업 결정 |

**면접 관점**: 이주환 팀장이 면접관이면 DAY-JA-VIEW를 먼저 물을 것 → 속도 질문 보정 답(노트 ①) 준비 완료. 그 뒤 "사내 업무 쪽은 해봤나"가 오면 REFLO. 김재헌 사원은 REFLO 페인포인트를 이미 긍정 평가했음(커피챗 ②).

세 프로젝트 공통 문장 후보: **"AI가 판단하게 두지 않고, 판단은 검증 가능한 모델·룰·원문에 맡기고 LLM은 해석과 설명에 쓴다. 그리고 AI가 만든 결과는 믿지 않고 측정한다."** — REFLO(Validation Agent 독립 재확인), MiRi(ML tool + LLM 설명), DAY-JA-VIEW(정답지·Ragas·테스트 우선)에서 세 번 반복된 사실.
