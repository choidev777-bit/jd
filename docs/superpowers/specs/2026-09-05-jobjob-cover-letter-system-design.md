# jobjob 자소서 생성 시스템 설계

작성일: 2026-09-05
상태: 승인됨 (대화에서 섹션별 확인 완료)

## 1. 목표

사용자 본인의 한국 기업 신입 공채 자소서(문항별, 글자 수 제한 있음)를 Claude Code 스킬로 생성한다.
재료(영상 팁, 샘플 자소서, 채용공고, 본인 이력, 기업 자료)는 inbox 폴더에 던지기만 하면 스킬이 분류·정제하고,
작성 스킬은 정제된 지식과 본인 프로필을 읽어 초안을 만들고 자동 검증한다.

### 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 대상 자소서 | 한국 기업 신입 공채 (문항별, 글자 수 제한) |
| 지원자 | 사용자 본인 1명 |
| 입력 방식 | 파일(profile, posting) 우선, 부족분만 대화 인터뷰 |
| 출력 형식 | 마크다운 기본. 요청 시 docx 스킬로 Word 생성 |
| 구조 | 스킬 2개(정리, 작성) + 지식 폴더 분리 |

### 채택하지 않은 대안

- 스킬 하나에 지식을 전부 넣기: 팁이 쌓이면 스킬이 비대해지고 매번 전부 로드됨.
- 하네스(다중 에이전트): 1인 사용에는 과함. 추후 검토 단계를 별도 에이전트로 분리해 확장 가능.

## 2. 폴더 구조

```
C:\jobjob\
├── inbox\                      뭐든 여기 던짐. 정리 스킬이 비움
│   └── processed\              처리 완료된 원본 보관 (삭제하지 않음)
├── knowledge\                  정제된 일반 지식. 작성 스킬이 참고
│   ├── principles.md           작성 원칙 총정리 (기본 원칙 / 선택 원칙 / 상투어 목록)
│   ├── question-patterns.md    자주 나오는 문항 유형과 접근법
│   ├── tips\                   팁 정리본. 출처별 파일 하나
│   ├── samples\                참고 자소서. 앞머리에 강점 메모 + "참고용" 표시
│   └── companies\              기업 분석, 면접 후기. 회사명별 파일
├── profile\                    사용자 본인 자료. 재사용
│   ├── resume.md               이력 요약 (학력, 활동, 자격, 수상)
│   ├── experiences.md          경험 카드 (경험당 상황·행동·결과·배운 점)
│   └── raw\                    원본 이력서, 포트폴리오 보관
├── applications\               회사별 작업 공간
│   └── YYYY-MM-회사-직무\
│       ├── posting.md          공고 정리 (문항, 글자 수, 직무 요건, 인재상)
│       ├── draft-v1.md ...     초안 버전
│       └── final.md / final.docx
├── docs\superpowers\specs\     설계 문서
└── .claude\skills\
    ├── jobjob-intake\          정리 스킬
    └── jobjob-write\           작성 스킬
```

핵심 규칙:
- 사용자는 inbox만 다룬다. 나머지는 스킬이 채우고 관리한다.
- knowledge(일반 지식)와 profile(본인 정보)은 절대 섞지 않는다. 섞이면 남의 경험이 자소서에 들어간다.
- applications는 회사마다 한 폴더. 초안 버전을 남겨 비교·재활용한다.

## 3. 정리 스킬: jobjob-intake

### 발동
- "inbox 정리해줘", "이거 분류해줘", `/jobjob-intake`
- 채팅에 텍스트를 붙여넣으며 "이거 팁이야" 등으로 전달하는 경우도 동일 흐름

### 동작 순서
1. inbox 파일(및 채팅 붙여넣기 텍스트)을 하나씩 읽는다.
2. 내용 기준으로 5개 유형 중 하나로 판별한다 (파일명 아님).
3. 유형별 정제 규칙을 적용해 목적지에 새 파일로 쓴다.
4. 원본을 `inbox\processed\`로 이동한다.
5. "무엇을 어디로, 어떤 원칙이 새로 추가됐는지" 한 줄씩 보고한다.

### 유형별 규칙

| 유형 | 판별 신호 | 목적지 | 정제 |
|---|---|---|---|
| 영상 팁 | 조언 어조, 캡션 형식, 출처 URL | `knowledge\tips\<출처>.md` | 출처 기록. 팁을 규칙 문장으로 재작성. `principles.md`에 병합 |
| 자소서 샘플 | 문항+답변 구조, 1인칭 서술 | `knowledge\samples\` | 앞머리에 강점 요약. "참고용" 표시 |
| 채용공고 | 회사명, 직무, 자격요건, 문항·글자 수 | `applications\<날짜-회사-직무>\posting.md` | 문항·글자 수·직무 요건·인재상 표로 정리. 폴더 없으면 생성 |
| 본인 자료 | 사용자 이름, 이력서 형식, 본인 경험 서술 | `profile\` | 이력→`resume.md` 병합, 경험→`experiences.md` 카드 추가, 원본→`raw\` |
| 기타 (기업 분석, 면접 후기) | 특정 회사 얘기, 공고·자소서 아님 | `knowledge\companies\<회사명>.md` | 날짜와 함께 추가 |

### 애매한 경우
- 판별이 애매하면 짐작하지 않고 묻는다. 특히 "본인 자소서 vs 남의 샘플"은 반드시 확인.
- 팁 충돌 시 `principles.md`에 두 견해를 나란히 적고 사용자에게 기본값을 묻는다.
  결정된 것은 "기본 원칙", 상황별로 다른 것은 "선택 원칙"으로 표시.

## 4. 작성 스킬: jobjob-write

### 발동
- "자소서 써줘", "<회사> 자소서 초안 만들어줘", "<문항> 다시 써줘", `/jobjob-write`

### 작성 흐름
1. **대상 확인.** 회사·직무 확정. `applications\`에 posting.md가 있으면 읽고, 없으면 공고를 요청하거나 문항·글자 수를 직접 묻는다.
2. **재료 수집.** `profile\experiences.md`, `resume.md`를 읽고 문항별 경험 후보를 고른다. `knowledge\companies\<회사>.md`가 있으면 인재상·직무 요건 반영.
3. **부족분 인터뷰.** 맞는 경험이 없거나 결과 수치가 빠진 부분만 묻는다. 한 번에 한 문항, 3~4개 질문 이내. 새로 나온 경험은 `experiences.md`에 추가.
4. **초안 작성.** `principles.md` 원칙과 `question-patterns.md` 접근법을 따른다. 샘플은 문체 참고만, 경험·문장은 가져오지 않는다. `draft-vN.md`로 저장.
5. **검증과 보고.** 자동 검증 후 문항별 글자 수·사용 경험 표를 보여준다. 수정은 다음 버전으로. "최종" 시 `final.md`, Word 요청 시 `scripts/md_to_docx.py`로 `final.docx`.

> 변경 기록 (2026-09-05 구현 중): Word 생성은 원래 anthropic-skills:docx 스킬에 맡기려 했으나, 그 스킬은 Node.js가 필요하고 이 PC에 없어 실패했다. 대신 python-docx 기반 변환 스크립트를 스킬에 동봉했다. 결과물은 동일하고 의존성은 `pip install python-docx` 하나다.

### 자동 검증
- **글자 수**: 공백 포함/제외 둘 다 표시. 제한 초과 또는 85% 미만이면 경고. `scripts\count_chars.py`로 수행.
- **경험 출처**: 초안의 모든 경험이 profile에 존재하는지 확인. 없으면 지어낸 것이므로 제거 후 재작성.
- **원칙 준수**: `principles.md` 기본 원칙을 문항마다 체크.
- **상투어**: `principles.md`의 상투어 목록으로 필터.

### 출력 형식 (draft 공통)

```
# <회사> <직무> 자소서 v1

## 1. 지원동기 (1,000자 이내)
[본문]
> 공백 포함 947자 / 공백 제외 712자 · 사용 경험: 캡스톤 프로젝트, 인턴십
```

## 5. 테스트

- 가상 채용공고 2개 + 가상 프로필 1개로 실행.
- 확인 항목: 글자 수 검사 정확도, profile에 없는 경험을 지어내지 않는지, 인터뷰가 짧고 필요한 것만 묻는지.
- 이후 실제 profile과 실제 공고로 재실행해 다듬는다.

## 6. 의존성

- Claude Code 스킬 시스템 (`.claude\skills\`)
- Python 3.12 (글자 수 스크립트, Word 변환 스크립트)
- python-docx 패키지 (Word 출력 시. `python -m pip install python-docx`)
