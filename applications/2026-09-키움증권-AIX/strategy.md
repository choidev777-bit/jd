## 0. 핵심 포지셔닝

- AIX는 기획·소통·PM 직무. "개발 잘한다"가 아니라 **"개발·기획 경험이 있어서 다우기술 개발자와 말이 통하고, 현업 요건을 문서로 정리할 수 있다"**
- 강점 연결: 사내 AI 업무 혁신 관심 = AIX의 대직원 효율화 방향 / 팀 프로젝트마다 백엔드를 맡음(현직자: 백엔드 인력은 희소) / 경영학 + 바이브코딩 독학(멘토 기준 "코드 읽기 + 결과물 제작" 충족)
- 세 프로젝트 공통 문장: **"AI가 판단하게 두지 않고, 판단은 검증 가능한 모델·룰·원문에 맡기고 LLM은 해석과 설명에 쓴다. AI가 만든 결과는 믿지 않고 측정한다."** (REFLO Validation Agent 독립 재확인 / MiRi ML tool + LLM 설명 / DAY-JA-VIEW 정답지·Ragas·테스트 우선)
- 서사 한 줄: 기획만 했던 사람(2017 코인썸) → 직접 만들어 팔아본 사람(2025 맵타민) → 팀과 조직 안에서 만들어 검증받은 사람(2026 세 번의 1·2·1위) → 이제 회사의 실제 문제를 풀고 싶은 사람. 맵타민 폐업이 "사업 → 조직 선택"의 증거
- 사고 패턴 공통: **심사자·경쟁자가 어떻게 비교할지 먼저 보고 빈 자리를 찾는다** (토스 실시간 ↔ 과거 / 지정주제 ↔ 자유주제)
- 읽는 사람(AIX 팀장·사원)은 최종 프로젝트 심사위원으로 DAY-JA-VIEW를 직접 봤다. 다른 지원자가 가질 수 없는 이점 → 대표 프로젝트로 가장 먼저 세움. REFLO는 "왜 사내 업무 AI인가"를 잇는 다리로만

## 2. 프로젝트별 프레이밍

### DAY-JA-VIEW
- **"참신한 아이디어"로 팔지 말고 "검증·구조·AI 통제"로.** AIX 두 명이 공통으로 팀워크를 낮게 봤고 김재헌 사원은 신선함도 낮게 봄
- 기획: "아이디어를 혼자 냈다"가 아니라 **"왜 만드는지를 기준으로 4번 폐기하고 다시 정의했다"**. 경쟁 서비스 분석(토스) → 빈 자리 발견(과거) → 데이터 가능성 확인(인포스탁) → 기획 확정 순서로. 박인준 주임이 AIX 업무의 핵심이라 한 "왜 만드는지를 개발팀에 설득"과 겹침
- 협업: 비개발자 팀원이 기여할 수 있게 **작업을 분해하고 완료 조건을 명시해 위임**(라벨링 1,000건씩, 판정 기준 사전 정의) / 프론트·UI/UX와 OpenAPI·화면 명세로 병렬 작업 / 지식 격차를 PRD·screen_spec 문서로 메움. ⚠ 팀원 설득·조율 에피소드 1개가 있어야 "독단"이 아니라 "설득"으로 읽힘
- AI 거버넌스(최대 차별점): **"AI에게 일을 맡길 때 무엇을 문서로 고정하고, 어디서 사람이 승인하고, 어떻게 검증하는가"를 직접 설계·운영한 경험.** 개발팀 자리에 AI가 있을 뿐 AIX의 요건 정의 → 문서화 → 개발팀 전달 → 검토 구조와 같음. JD "AI 거버넌스(위험평가 등) 운영"에 직결
- 자소서 소재 후보: A 본질 기준 기획 / B AI 작업 거버넌스(CLAUDE.md 규칙·승인 3원칙·세션 분리 리뷰) / C AI 검증 설계(블라인드 정답지 → 정확도 루프 → dev/test 분리 → Ragas) / D 요건 정의·문서화(PRD·화면 명세·API 계약·ADR) / E 제약 대응(키움 API IP 차단 → 고정 IP 인프라, 망분리 환경 경험 가점과 연결) / F 위임·분해(비개발자 4명이 4,000건 기여) / G 학습 속도(해커톤 패배 원인 온톨로지를 한 달 만에 습득·적용)
- 용어 주의: 온톨로지, Ragas, gold set, Context Precision 등 쓴 용어는 전부 1분 안에 비개발자에게 설명 가능해야 함. 자소서 본문은 "무엇을 왜 했고 어떻게 검증했나" 수준, 수치·스택은 면접용

### MiRi
- 자유주제 선택은 **확률 표현 유지**: "지정주제는 안 된다"가 아니라 "자유주제가 수상 확률이 높다고 봤다". 1위가 지정주제(준법)였던 사실과 충돌하지 않음
- **현장 검증 후 폐기** 장면은 DAY-JA-VIEW에 없는 소재: "회장이 강조한 영역이라 매력적이었지만 현장(외국인금융센터)에 가서 확인하고 접었다". 실제로 JB가 국내에서 가장 앞선 영역(외국인 대출 점유율 70%, 10개국어 콜센터)이라 판단이 정확했음
- 데이터 한계를 먼저 말하기: "실데이터 접근이 불가능한 조건에서 공공 API 실측 + 실데이터 proxy + 합성으로 파이프라인을 검증했다". "리뷰를 LLM으로 평가해 ML에 넣었다"고만 쓰면 실데이터로 오해됨
- 예선 통과를 "문서 제출"이 아니라 **"현직자가 읽고 만들 가치가 있다고 판단한 문서 + 그 문서로 팀·AI가 구현"**으로 (523 → 13, 상위 2.5%)
- 1위(FinProof) 비교 답: "1위 팀이 다국어 홍보물의 사회적 맥락 리스크를 잡기 위해 국가별 민감 사건·상징을 지식 그래프로 구조화한 걸 봤습니다. 텍스트 검색으로는 못 잡는 관계를 구조로 잡는다는 게 인상적이어서 온톨로지를 공부했고, 다음 프로젝트에서 '소재 1개에 테마 9개가 반응하는' 관계 문제에 적용했습니다." 왜 2위였는지는 모름 → "공통점은 AI 결정 범위를 제한하고 사람이 최종 판단하게 한 것, 차이는 1위가 근거 구조(법령·사례 인용, 지식 그래프)를 더 깊게 만든 것"
- AIX 연결: 회장 메시지 → 현장 인터뷰 → 폐기는 AIX의 니즈 수집 → 미팅 → 검토 프로세스와 동일. "여기 와서 뭐 하고 싶냐"에 "회사의 실제 숫자에서 문제를 찾는다"는 방식으로 답할 근거

### REFLO
- **"키움도 작년에 AI 리서치 리포트를 구축했다"를 먼저 말하고** → 우리는 초안 생성보다 검증·정합성(전 분기 데이터 정리, 팩트체크 에이전트)에 집중했다 → 실제 병목인 검수 단계를 줄이는 방향으로 프레이밍. 한계(의견 대체 불가, 검수 필수)를 먼저 인정하고 그 안에서 시간을 어디로 돌려주는지 말하기
- 인터뷰는 "3명"이 아니라 **"쓰는 쪽(키움·NH 현직) · 운영했던 쪽(대신 전 센터장)"**. 두 증권사 현직을 물었으니 "한 회사 특수 사정이 아니라 업계 공통 문제". 키움 현직 인터뷰는 "자동화 도입 후에도 남는 문제(검수·전 분기 흔적)를 겨냥했다"로, 전 센터장 인터뷰는 "리포트가 회사 이름으로 나가는 무게" → 검증 에이전트를 넣은 이유로 연결
- 섭외는 **리멤버로 현직 애널리스트에게 직접 연락해 미팅을 잡았다**는 쪽에 중심. AIX에서 현업을 찾아가는 방식과 같고 반복 가능한 행동. 전 센터장 소개자는 언급하지 않음. 물으면 "가족 지인 소개"까지만
- 지원동기·직무이해에서 DAY-JA-VIEW 뒤에 붙는 다리로만. 김재헌 사원은 REFLO 페인포인트를 이미 긍정 평가함

### 맵타민
- AI 활용 소재: "AI를 잘 다룬다"를 증명하려고 실제 유료 사용자를 만들었다는 접근 자체가 차별점. 혼자 설계·구축·운영·과금까지 → AI 면접 3점 구간("즉시 투입 가능") 근거
- 문제해결 소재: 비용이 사업성을 막는 벽 → 절약(캐시·이미지 대체)으로는 한계 → 접근 자체를 바꿔 1/30 → 측정으로 검증. "구조를 바꿔 문제를 푼다"
- 소상공인 도메인: 맵타민(광고 효율) → MiRi(대안신용). 사장님 인터뷰에서 시작한 두 서비스
- **프록시·IP 변경·차단 우회 표현 제거.** "공개 검색 결과 페이지를 렌더링 없이 최소 요청으로 받아 비용을 1/30로 줄이고 계측으로 확인"에 집중
- 폐업이 오히려 이탈 우려의 반증

## 3. 면접 준비

### 3-1. AI활용능력평가면접 (있을 경우, 0~3점 가점)
- 프로젝트 기술 설명을 3단계 깊이로: 개요 → 아키텍처 → 구현 디테일·사용 도구. 2~3점 기준("시스템을 구축했다")이 드러나게
- **어디까지 직접 짰고 어디까지 AI 도구로 짰는지** 솔직하게 구분
- 망분리·보안 제약을 이해하고 있다는 점 어필: 사내 LLM만 쓸 수 있는 상황에서 어떻게 설계할지
- 리서치 에이전트 + 검증 에이전트 구조, 프레임워크, DB·벡터스토어, 프롬프트 설계, 할루시네이션 방지 로직을 기술 스택 수준까지

### 3-2. 1차(팀장급) 면접 시뮬레이션
- 패턴: 자소서 문구 하나 → "그게 뭐냐" → 키움/증권 상황에 적용 → 우리 서비스(영웅문) 사용 경험 → AI 활용 의견 → 마지막 어필
- 자소서 문구마다 "그게 뭐냐 → 키움에서는 어떻게 적용되냐" 준비
- 질문 5~6개 + 꼬리질문 1개씩. 답변 짧고 명확하게. 겸손하지만 씩씩하게
- 2차(실무진)는 "내 후배로 왔을 때 말이 통할까"를 봄. PT 면접 가능성: "문제 정의 → 제약(망분리·컴플라이언스) → 해결 → 검증"으로 구조화 연습

### 3-3. 필수 답변 (준비 필요)
- **"여기 와서 뭐 하고 싶냐"**: 사내 LLM 활용도 제고·기능 개선(현직자 실사용은 "보고서 문구 다듬기" 수준) / AI 활용 가이드라인·거버넌스 수립 참여(아직 확립 중) / 리테일 외 부문(S&T·IB·운용 지원, 컴플라이언스 검토 자동화) AI 도입 중 1~2개 구체화
- **"AI 잘하면 어디든 갈 수 있는데 왜 키움·왜 증권인가"**(설명회에서 임원급이 직접 던진 질문): 2017 영웅문 HTS 접점, KDA 4개월, 리서치·테마 프로젝트, 사장의 AI 강조와 제약을 아는 지원자 → 답변 초안 작성 필요
- **DAY-JA-VIEW 속도 질문 보정 답**(심사 때 "MVP라 생각 못 했다"고 답함): 조회 패턴 기준 인덱스·집계 테이블 → Redis 캐시 → 그 다음 그래프DB 전환 검토. "지금 구조에서 어디가 먼저 병목이 될지"까지
- **"AI가 코드 다 짰으면 네 역량은 뭐냐"**: 요건·명세·완료 조건을 정의하고, 계획을 검토·승인하고, 테스트와 세션 분리 리뷰로 검증하는 시스템을 설계·운영한 것. AI가 만든 결과를 믿지 않고 측정한 것
